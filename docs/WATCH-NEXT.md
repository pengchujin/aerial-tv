# Watch Next 设计

更新日期：2026-11-03。状态：基础接入已编码，release 构建与单元测试通过；完整 lint 仍有基线错误，尚未做真机验证。实际接点与验证记录见第 17 节。

本文记录本轮讨论收敛后的方案，供后续实现与验收使用。布局、导航和开关规则以本文为准；尺寸、动画时长及缓存参数是实现初值，需结合电视实测调整。

设计阶段交付为文档与 HTML 交互示意；最初实施范围为基础接入。用户随后明确批准背景增强，并要求复用现有背景与切换代码；当前正在独立补充该阶段，具体接点与验证见第 17 节。真机验证仍单独记录。

本轮增加实施约束：优先减少对上游现有文件的修改，降低 fork 后续同步成本。功能代码放在 `app/` 内的独立 `watchnext/` 包，现有首页只承担必要的布局、焦点与入口连接；不复制一套首页，也不为此重构全局设置、壁纸或播放系统。代码复用、高内聚低耦合落实为：同一规则共用一个实现，每类状态有明确的负责者，宿主通过少量只读值和回调连接功能。具体职责、复用点及边界见第 13 节。

实施分为两部分：**基础接入**保留原背景，完成授权、来源开关、全局汇总、局部图片、节目操作及循环；**背景增强**实现此前“大横图临时替换全屏背景”的设计。背景增强不是基础接入的前置条件，已由用户明确追加授权；是否实现与验证应以第 17 节为准，不能以 HTML 示意代替实装。

## 1. 最终行为

首页上方展示所有已开启来源的 Watch Next，按记录的最近相关时间倒序排列；下方保留应用网格。选中任何 App、任何一行，都不改变节目列表范围，也不重置当前节目。

| 项目 | 规则 |
| --- | --- |
| 来源栏 | 只显示当前节目来源的 **App 图标 + App 名称**，例如「［图标］影视 C」。不追加「· 继续观看」等文字 |
| 汇总范围 | 所有已开启来源的有效记录；包名只用于识别来源和执行来源开关 |
| 汇总入口 | 不设置「全部继续观看」按钮，也没有全局／单 App 视图切换 |
| 首次进入 | 有可显示记录时选中第一条的「继续播放」；没有记录时选中第一个 App |
| App 聚焦 | 上方保持全局列表；满足条件时自动循环预览 |
| 节目聚焦 | 停止自动轮播，左右手动双向循环切节目：末项向右回首项，首项向左回末项；确定继续播放 |
| 返回键 | 沿用现有网格回首排、首排按设置进入屏保的行为，不用于进入节目区 |
| 没有记录 | 恢复普通桌面及用户原来选择的背景 |
| 有记录但没有图片 | 原背景上显示该节目的可用信息和播放按钮，仍参与列表与轮播 |
| 个性化总开关关闭 | 隐藏全部节目内容及节目图片、停止读取与轮播，恢复普通桌面 |

“始终汇总”不绕过系统授权或用户关闭的来源。长按菜单仍能决定某个 App 的记录是否加入汇总，但移动焦点不再执行来源过滤。

## 2. 数据从哪里来

标准来源是 Android TV 的 TvProvider 表：

```text
content://android.media.tv/watch_next_program
```

视频 App 主动把允许共享的节目写入该表，Aerial 通过 `ContentResolver.query()` 读取。Aerial 不需要逐个启动 App，也不遍历每个 App 的私有数据库。

参考项目 Luma 的 `src/dev/luma/tv/UpNextWidget.java`：

- `watchNext()` 一次查询共享表，按包名识别来源，在内存中按时间倒序排序。
- 同时读取标题、季集、图片 URI、播放入口、播放进度及时间等字段。
- 图片在后台加载并缓存；优先缩略图、其次海报，是它自己的选择策略，不代表缩略图一定更清晰。
- Luma 还会用“最近使用的 App”填补卡片。这部分来自使用情况访问或它自己的启动记录，不属于 Watch Next，Aerial 本功能不混入这类数据。

Watch Next 不是完整观看历史。没有记录可能是 App 未发布、尚无合适节目、记录已被删除，或记录不对普通桌面公开。仅凭空结果无法区分这些原因。

标准 Watch Next 路径从 Android 8.0 / API 26 起提供；本期针对完整版 `app/`。旧系统缺少接口时不显示入口，`lite/` 不接入这套方案。Android 版本足够也不代表厂商固件一定允许读取。

## 3. 系统权限与显示开关

### 3.1 三个独立条件

| 状态 | 所属方 | 含义 |
| --- | --- | --- |
| `systemPermissionGranted` | Android 系统 | Aerial 是否获得 `android.permission.READ_TV_LISTINGS` |
| `masterEnabled` | Aerial 偏好 | 用户是否允许首页展示 Watch Next |
| `sourceEnabled(packageName)` | Aerial 偏好 | 是否把这个 App 发布的记录加入全局列表 |

系统权限授予的是 **Aerial 整个应用**，不是针对某个视频 App 单独授予。此前讨论中的“App 授权”在实现上应称为“来源显示开关”，避免让用户误以为还要向视频 App 申请一次系统权限。

来源的实际开启状态为：

```text
effectiveSourceEnabled(packageName) =
    systemCapabilityAvailable
    && systemPermissionGranted
    && masterEnabled
    && sourceEnabled(packageName)
```

AOSP 中，`READ_TV_LISTINGS` 允许普通应用读取其他 App 的公开、可搜索记录；它不授予全部私有节目或观看历史的访问权。通知监听、使用情况访问、桌面守护均不是标准查询的必要条件。

参考 AOSP Android 14 的 TvProvider 将该权限声明为 `dangerous`，可以发起运行时权限请求。厂商实现仍需通过 `PermissionInfo` 检查真实声明及保护级别：已授予则直接继续，明确缺少声明则判为不支持，未授予且基础类型为 `dangerous` 才发起运行时请求。其他不可由普通应用取得的授权不能通过反复弹框、修改安装脚本或加入额外特权来解决；授权成功也不保证存在可读记录。

### 3.2 App 长按菜单

入口位于应用图标的长按菜单，名称保持「显示继续观看」。它是来源开关，不是播放命令。

- 对普通 App 图标提供；文件夹、信号源及 `shortcut != null` 的合成磁贴不套用包名开关。这些磁贴的 `packageName` 可能是内部入口键，不能当作 Provider 的来源包名。
- 沿用原 App 菜单的可用条件；儿童与长辈模式中原本不允许长按菜单时，不额外开放来源开关入口。
- 菜单是否出现取决于系统是否具备标准 Watch Next 读取能力，不依赖这个 App 当前有没有记录。
- API、Provider 或权限声明明确不存在时隐藏该项；尚未授权、空结果及一次读取失败不能当成“不支持”。
- 总开关关闭时，所有 App 菜单的该项都显示关闭；内部保留各来源偏好。
- 点击开启时，同时开启该来源与总开关。缺少系统权限时先走授权，成功后完成本次开启请求并刷新数据；拒绝或取消时不显示为开启成功。
- 已开启时点击关闭，只关闭该来源，立即从全局列表移除它的记录。
- 如果只是总开关关闭而来源偏好仍为开启，再点击该 App 的开启操作，会重新打开总开关；其他原先开启的来源也按各自偏好恢复。

“没有记录”不会自动关闭来源，也不会隐藏菜单。开启后若该来源仍无记录，上方可以继续显示其他已开启来源的节目。

授权请求只由用户主动操作触发。系统不再弹出授权对话框时，可引导到 Aerial 的应用详情／权限设置；不能在刷新或每次回到桌面时重复弹授权。

### 3.3 个性化总入口

个性化中提供 Watch Next 的总开关，并在同一入口表达系统授权状态：未授权时开启触发授权；已授权时控制是否显示。

关闭总开关时：

1. 立即隐藏节目文字、播放按钮、圆点及节目图片，恢复普通桌面背景。
2. 取消轮播、图片预取及进行中的刷新，移除 Provider 监听；不能让迟到结果重新显示节目。
3. 保留来源偏好，供下次开启恢复。
4. 不撤销系统权限。

显示偏好与系统授权分开处理。用户暂时隐藏内容后可以直接恢复；撤销授权应在系统权限入口执行。平台没有适用于所有目标系统的通用“关闭显示即自撤销”接口；API 33 起的自撤销还涉及异步执行和进程终止，不绑定到普通显示开关。

从系统设置返回及每次实际读取前重新检查授权。权限被撤销后立即停止展示，不能继续使用旧缓存绕过授权状态。

## 4. 能力、加载与空数据状态

内部状态必须能区分下列情况，不能统一存成空列表：

| 状态 | 判断依据 | 首页处理 |
| --- | --- | --- |
| 系统不支持 | 接口所需的系统能力明确缺失 | 普通桌面；隐藏不适用入口 |
| 未授权 | 系统权限未授予 | 普通桌面；保留可触发授权的入口 |
| 未开启 | 总开关关闭 | 普通桌面；停止查询和监听 |
| 尚未加载／加载中 | 没有完成本轮查询 | 不把它显示为“暂无记录”，不阻塞应用导航 |
| 查询成功但无可显示记录 | 成功读表，过滤后为零条 | 普通桌面；来源开关保持原状态 |
| 有记录 | 过滤后至少有一条有效记录 | 显示节目区 |
| 读取失败／暂不可用 | Provider 拒绝访问、返回异常等 | 无有效快照时回普通桌面；设置页保留可解释状态 |

成功查询后“某个来源记录为零”和“未发现这个来源的记录”，对展示来说可以归为同一种空结果，但不能推导出该 App 永久不支持。未查询、未授权和查询失败不属于这种空结果。

同一授权及来源配置下，短暂刷新失败可以保留本次会话的有效快照；关闭总开关、撤销权限或关闭来源时，必须立即应用新的可见范围。

## 5. 数据结构与排序

### 5.1 记录字段

原始模型保留可空字段，不把“未知”转换成虚构的时间或进度。

| 应用字段 | Provider 列 | 用途 |
| --- | --- | --- |
| `providerRowId: Long` | `_id` | Provider 行标识 |
| `sourcePackage: String` | `package_name` | 识别来源、关联 App 信息及来源开关 |
| `title: String?` | `title` | 节目标题 |
| `episodeTitle: String?` | `episode_title` | 单集标题 |
| `seasonDisplayNumber: String?` | `season_display_number` | 季编号，保留字符串格式 |
| `episodeDisplayNumber: String?` | `episode_display_number` | 集编号，保留字符串格式 |
| `contentType: Int?` | `type` | 电影、单集等内容类型 |
| `watchNextType: Int?` | `watch_next_type` | 继续、下一集、新内容、待看等类型 |
| `posterUri: String?` | `poster_art_uri` | 海报候选 |
| `thumbnailUri: String?` | `thumbnail_uri` | 缩略图候选 |
| `posterAspectRatio: Int?` | `poster_art_aspect_ratio` | 海报比例枚举 |
| `thumbnailAspectRatio: Int?` | `poster_thumbnail_aspect_ratio` | 缩略图比例枚举；注意真实列名带 `poster_` 前缀 |
| `intentUri: String?` | `intent_uri` | 来源提供的播放入口 |
| `lastPlaybackPositionMs: Long?` | `last_playback_position_millis` | 播放位置 |
| `durationMs: Long?` | `duration_millis` | 总时长 |
| `lastEngagementTimeUtcMs: Long?` | `last_engagement_time_utc_millis` | 排序时间 |
| `browsable: Boolean?` | `browsable` | 是否允许展示；明确为 false 时排除 |

稳定身份使用 `(sourcePackage, providerRowId)`。不同 App 的同名节目不合并，因为播放入口、账号及进度可能不同。

App 图标和名称从现有应用目录及缓存取得，不要求 Provider 重复提供。来源名称沿用 Aerial 中该 App 的名称；正式界面使用真实图标，示意中的字母只是虚构 App 的占位图。长名称单行省略，图标缺失时使用现有通用占位图，不影响节目展示。

首页适配层根据现有 `apps`、`folderApps`、`hiddenApps` 等目录快照提供来源信息，不修改 `AppEntry` 或应用枚举规则。当前 `HomeViewModel.entry()` 不覆盖隐藏 App，不能仅因它返回空就认定来源已卸载；来源可用性需结合完整目录或包管理器的实际结果判断。普通隐藏不等于卸载，也不自动改变 Watch Next 来源偏好。

宿主分别提供**来源元数据快照**与**当前模式允许展示、操作的来源范围**。受限模式下 `apps` 已筛选，但 `folderApps / hiddenApps` 仍保留普通目录，不能把三者合并后当成展示许可；`entry()` 非空也不代表允许启动。有效节目只取宿主允许的普通 App 来源，不从信号源播放器、快捷入口或守护用的 `allowedPackages` 扩大范围。模式和锁状态改变时立即重新派生展示／交互资格，不等待 Provider 再次刷新；功能不自行重建受限模式、时间限制或 PIN 规则。

### 5.2 时间含义

`last_engagement_time_utc_millis` 不一定是观看时间：

| Watch Next 类型 | 该时间通常表示 |
| --- | --- |
| `CONTINUE = 0` | 最后观看这条内容的时间 |
| `NEXT = 1` | 最后观看上一集的时间 |
| `NEW = 2` | 新一集的发布时间 |
| `WATCHLIST = 3` | 加入待看列表的时间 |

全局列表接纳这些 Watch Next 类型，因此准确表述为“按最近相关时间倒序”。展示时间时不能把所有类型都写成“上次观看”。时间缺失时不显示时间说明，排序放在末尾；时间相同再用稳定键排序，避免刷新抖动。

### 5.3 有效记录与进度

- 来源已开启、App 仍可用、记录允许展示，才进入有效列表。
- 缺图不影响有效性。缺标题使用本地化的通用标题，不把整条记录丢弃。
- 缺少深链但能正常启动来源 App，可以保留；点击后只能打开 App，不能承诺定位到节目。
- 深链和普通启动入口都不可用时，不作为可操作节目展示，避免默认焦点落在死按钮上。
- `durationMs > 0` 且播放位置有效时显示进度，比例限制在 `0..1`。未知时长或位置时隐藏相应信息，不伪造进度。
- 刷新后尽量保持当前稳定键；当前记录被移除时选相邻的可用项。列表全部变空时回普通桌面和有效的 App 焦点。

## 6. 读取、刷新与缓存

一次刷新查询共享表，拿到快照后在内存中执行来源开关过滤、字段校验、稳定排序和界面更新。不是对 App 列表逐个查询。

1. 查询放在后台 I/O 任务中，使用所需字段的 projection，及时关闭 Cursor。
2. 普通查询使用 `selection = null`、`selectionArgs = null`。不能假设普通调用者可以任意写 SQL 条件筛选其他 App。
3. 可使用标准 `sortOrder`；厂商不兼容时使用内存排序。兼容投影缺列时只能进行有界回退，不无限重试。
4. 首页可见且功能开启时监听 Provider 变化，并合并短时间内的重复通知。
5. 授权完成、来源开关变化、回到桌面时进行必要刷新。后台及关闭功能时取消监听，返回前台再补一次刷新。
6. 图片解码与透明边缘预处理和读表分开，异步执行。先展示可用文字，不等待全部图片加载完；基础接入只准备第 7 节的局部图片，不为每个节目生成全屏背景或磨砂。全屏裁切和磨砂仅属于背景增强。
7. 缓存当前项与少量相邻图片，按目标显示尺寸解码；缓存有容量上限，并响应内存回收。
8. 图片和查询结果带来源／记录身份及请求代次；用户已切换、关闭功能或撤销授权后，丢弃迟到结果。

读取资格与轮播资格分别控制。系统支持、授权有效、总开关开启且首页在前台时，零条记录也应保留 Provider 监听；有节目但焦点停在节目区时仍可刷新，只暂停轮播。不能用一个 `active` 值同时表达“允许读表”“存在节目”“允许自动切换”。

8 秒轮播只切换内存中的当前项，不重新查询 Provider。查询耗时、取图耗时、图片预处理耗时分别测量；不能在没有真机数据时承诺固定毫秒数。

## 7. 首页布局与图片

按项目 960×540dp 画布设计。节目区放在应用网格的滚动容器外；下方应用区独立滚动，保证当前 App、名称及焦点外框完整可见。

节目区按顺序包含：

1. 节目标题。
2. 有效的季集、单集标题或类型信息。
3. 可用的进度、剩余时长及时间信息。
4. 来源 App 图标与「继续播放」按钮同排，图标在按钮左侧；不再单独显示来源名称行，名称保留为图标的无障碍描述。
5. 节目区底部、相对整屏水平居中的圆点指示器。

2026-11-03 按用户追加要求，双排 App 布局恢复有效信息：优先一行季／集、剩余分钟、年份、分类及评分，长度超限省略尾部；余下高度容得下完整行时，再显示一行单集标题（优先）或简介。进度有效时保留独立细进度条及按钮内进度。空值不生成占位，空间不足不显示半行文字；宽松布局仍显示较完整的资料。

单排布局保留较大的标题和画面；双排布局收紧标题、元信息和间距。本轮示意将单排文字区设为 440dp、右侧图片列宽度上限设为 384dp；双排文字区为 520dp、图片列宽度上限为 288dp，以适应不同的可用高度。这些是可调整的布局初值，需验证长标题、多语言和真实素材的效果。布局要考虑现有列数、App 名称设置和焦点放大，不能只在“五列、不显示名称”这一种组合下成立。按用户在代码审查中的最新要求，节目区出现时保留原有大小时钟、左右位置、日期天气和屏保接力；由节目区适配时钟，不能关闭时钟或强制替换为胶囊时间。

图片策略如下：

| 可用素材 | 显示方式 |
| --- | --- |
| 比例、实际像素适合铺满的横图 | 基础接入仍按局部图片规则显示；背景增强才允许临时作为全屏节目背景 |
| 适合局部展示的横缩略图、竖版海报或方图 | 保留原背景，按可用图片区高度的百分比确定目标高度，保持原图比例缩放，在右侧图片列内水平、垂直居中 |
| 图片清晰度不足以用于计算出的显示尺寸 | 尝试同节目的另一候选；仍不合适时按无图展示，不因低清随意改变高度比例或挤动邻居 |
| 两种图片都缺失、不可读取或加载失败 | 保留原背景，只显示该节目的其他信息和按钮 |
| 候选图片尚在加载 | 使用原背景等待，不能把上一节目的图片当成这一条的图 |

Provider 只提供 URI 及可选比例，不保证图片是高清大图。应读取图片实际尺寸后判断候选的清晰度，并使用实际长宽比计算等比显示尺寸；图片列和文字区的布局不能跟着原图像素大小改变。`video_width` / `video_height` 是视频尺寸，不能拿来判断海报比例或清晰度。

保留海报和缩略图两个候选。局部展示优先选择同节目中清晰度合适的横缩略图，其次使用海报等候选；不能只因 URI 字段名是缩略图就认定它更清晰。一个加载失败或清晰度不足时可以尝试另一个。记录没有图片时仍然占一个圆点，也仍参与自动轮播。

局部图片以高度为主导：目标高度为扣除指示带及安全间距后的可用图片区高度乘以 `heightFraction`，本轮建议初值为 85%。保留源图长宽比，不裁切、不拉伸；采用 `ContentScale.Fit` / Contain 等比显示，并在右侧图片列内水平、垂直居中。同一布局内、未触发宽度或动画安全限幅时，横图、方图和竖图高度一致，宽度随原图比例变化，这是当前的展示要求。

百分比表达目标高度及上限，不能导致图片溢出。过宽或超宽图片按右侧实际可用宽度再次等比缩小，保护文字和安全间距；这种情况下实际高度可以低于 85% 目标，宽度安全优先。节目标题仍在左侧独立显示，原图边缘按第 7.2 节渐隐。

`heightFraction` 是待真机验证的设计参数，不是新增产品设置。HTML 示意中的高度比例滑动对照仅帮助比较视觉效果，不能据此扩展正式设置项。

### 7.1 图片区与圆点区域的边界

**2026-11-03 B 方案更新：** 用户确认采用立体圆角卡片及更大的来源图标。下文早期几何示例保留作设计记录；当前实现以第 17.10 节为准：局部图允许等比放大，每侧预留 12dp 阴影/动画空间，图片区与指示带间隔 8dp，圆点与 App 底板仍间隔 12dp。

局部海报／缩略图与圆点必须使用独立布局区域，不能分别写固定坐标后依赖层级覆盖。提高圆点的 `zIndex` 用来保证绘制顺序，不能替代图片与指示带之间的避让。

从实际应用底板的顶部向上计算，建议初值如下。`artTop` 是该布局允许图片区开始的位置，`textRight` 是实测文字区右边界，`rightInset` 为右侧留白，`layoutArtWidthLimit` 是当前布局的图片列宽度上限。图片列覆盖整个 `availableHeight`，其宽度必须同时受实测剩余宽度约束；百分比的基准是这段已排除指示带与安全距离的高度，不是全屏或应用区的高度。`sourceAspect` 使用有效的原图宽度除以高度。

```text
indicatorBottom = appShelfTop - 12dp
indicatorTop    = indicatorBottom - 24dp
artBottomMax    = indicatorTop - 16dp
indicatorCenterX = canvasWidth / 2

availableHeight = max(0dp, artBottomMax - artTop)
columnWidth     = max(0dp, min(layoutArtWidthLimit,
                             canvasWidth - rightInset - textRight - 24dp))
columnLeft      = canvasWidth - rightInset - columnWidth
columnTop       = artTop
columnHeight    = availableHeight

heightFraction  = 0.85
motionInset     = 8dp  // 4dp on each side
sourceAspect    = sourceWidth / sourceHeight
targetHeight    = availableHeight * heightFraction
imageHeight     = min(targetHeight,
                      max(0dp, availableHeight - motionInset),
                      max(0dp, columnWidth - motionInset) / sourceAspect)
imageWidth      = imageHeight * sourceAspect
imageLeft       = columnLeft + (columnWidth - imageWidth) / 2
imageTop        = columnTop + (columnHeight - imageHeight) / 2
```

- 圆点独占固定 24dp 高、最大 288dp 宽的指示带，宽度包含内边距；整条带固定在节目区底部的屏幕水平中心，960dp 画布上中心为 `x=480`。该区域底部与应用底板至少间隔 12dp。
- 局部图片区的底边与圆点区域顶部至少间隔 16dp。图片、四边透明渐变及转场都限制在图片区内；即使图片边缘已经透明，也不能把它的布局区域伸入指示带。
- 同一布局使用相同的可用高度与 `heightFraction`，未触发安全限幅时实际图像高度一致，宽度由 `imageHeight × sourceAspect` 得到。保持完整原图比例，不按统一比例裁切或拉伸。原图像素分辨率只影响候选清晰度判断与解码，不能直接作为 dp 尺寸；低清时换候选或按无图展示。
- 图片列本身右对齐，其内部图像始终水平、垂直居中；列覆盖完整可用高度，不跟着当前图像尺寸收缩。右侧图片列与左侧文字至少间隔 24dp，不使用可见底板。源图比例只影响图像尺寸与宽度限幅，不改变图片列、文字区或圆点的位置。
- 图像的目标高度还需受 `availableHeight - 8dp` 与 `(columnWidth - 8dp) / sourceAspect` 限制，确保每边至少有 4dp 动画余量。宽度不足时同时等比缩小宽高，不允许图像覆盖文字；不能为了严格达到 85% 而越界。图片数据无效或可用宽高不足时走无图路径。
- 固定的是父级图片列和周围布局。局部图像内容仍可按第 7.2 节做 `0.98 → 1` 的淡入缩放；动画只作用于绘制内容，不能改变父列或相邻文字、按钮、圆点的测量和位置。
- 圆点数量变多时保持单行及固定高度，只有指示带内部的圆点轨道横向滚动，外部指示带保持居中；当前点的滚动位置根据实际可见宽度计算，不使用固定偏移量，不影响图片区大小。
- 单排／双排、列数、名称设置或焦点外框改变后，按实测布局重新计算边界。切换布局前取消旧图片动画；新的淡入或位移不得越出预留图片区。
- 加载、缺图或取图失败时只隐藏图像，保留该布局的文字宽度与图片列位置，圆点不移动，不因新图片到达挤动邻居。可用空间过小时优先保留文字、播放按钮和指示器，局部图片可以不显示；不能让最小动画内缩反而造成越界。
- 背景增强中，作为全屏背景的横图按背景路径绘制，不受局部图片区约束；圆点区域的位置和对比度规则保持一致。基础接入不增加这条全屏绘制路径。

以当前五列示意为例：文字区左侧和图片列右侧留白均为 56dp。单排应用底板顶部约 `y=385`，圆点区域为 `349..373`，图片列为 `102..333`，可用高度 231dp；双排底板顶部约 `y=272`，圆点区域为 `236..260`，图片列为 `76..220`，可用高度 144dp。指示带取最大宽度时横向占 `336..624`，较短时仍以 `x=480` 为中心。

下表按 85% 目标高度计算，图片尺寸均为“宽 × 高”；这些常见比例在示例空间内均未触发宽度限幅。

| 当前示意布局 | 文字区 / 图片列宽度 | 可用高度 / 85% 目标高度 | 2:3 竖海报 | 1:1 方图 | 16:9 横缩略图 |
| --- | --- | --- | --- | --- | --- |
| 单排 | 440dp / 384dp | 231dp / 196.35dp | 130.9×196.35dp | 196.35×196.35dp | 约 349.07×196.35dp |
| 双排 | 520dp / 288dp | 144dp / 122.4dp | 81.6×122.4dp | 122.4×122.4dp | 217.6×122.4dp |

例如 3:1 超宽图会触发宽度限幅：单排约为 376×125.33dp，双排约为 280×93.33dp，高度低于各自 85% 目标，但仍在固定图片列内水平、垂直居中。尺寸、比例参数、文字宽度及留白均可在真机验证后调整，这些坐标只用于说明约束，实际实现应从布局结果推导，不能硬编码为所有配置通用。

### 7.2 局部图片的立体卡片与转场（已按确认的 B 方案更新）

用户确认 B 方案后，原四边透明渐隐改为清晰的圆角卡片。图片按可用区域等比放大或缩小，不因源图分辨率较小而拒绝显示；不做固定比例裁切或透视变形。全屏背景继续使用独立的清晰度门槛。

- 14dp 圆角、10dp 静态 elevation 阴影及 0.75dp 的细微渐变边缘，形成轻微悬浮感。阴影由显示层处理，Artwork 只负责后台加载和等比缩放；不再逐像素生成四边透明遮罩。
- 每侧预留 12dp 阴影及动画空间。实际图片与动画仍限制在图片区，不能侵入文字、圆点或 App 焦点区域。正常竖图、方图和横图均按 Contain 计算；超宽图继续受宽度限制。
- 局部图补齐退出／进入：旧图跟随内容组的 120ms 退场，淡出、1→0.98 缩小并沿导航方向退移最多4dp；在不可见的内容交接点移除旧图。新图按320ms淡入、0.98→1缩放并从对应侧最多4dp处回位，和内容组的进入透明度相乘；同一节目迟到的图片也只在准备成功后淡入。使用 Motion.EaseOut，左右镜像，减少动态效果时直接显示，不增加常驻动画。
- 左侧文字的独立椭圆暗斑改为横向渐变对比层，上下自然淡出；范围止于节目区，不覆盖 App 底板及磁贴。不做实时全屏模糊。
- 全屏节目背景仍复用原背景绘制链与转场，不使用局部卡片的圆角或阴影。

### 7.3 原背景与图片来源

基础接入保持原背景路径，包括“跟随 App”、图片、航拍和视频壁纸；局部海报只在右侧增加有限面积的内容，不修改 `Wallpapers.selectedId`、壁纸缓存或播放器状态。节目区关闭或缺图时沿用原背景，无需执行壁纸选择的切换与恢复。

背景增强中的节目背景属于功能内部的临时展示状态，同样不写入用户壁纸选择。关闭功能、没有有效记录或退出节目背景后，恢复用户原来的背景模式；原模式是“跟随 App”时，仍按现有模式生成背景。

标准图片 URI 可能来自 `content://`、`android.resource://` 或远程地址。远程加载和全列表预下载仅使用当前有效节目列表的 Provider 图片 URI，不添加内容服务、SDK 或额外数据源。HTTP/HTTPS 图片直接请求原地址，沿用既有超时、重定向、取消和大小上限；失败不写入缓存，不转发至其他图片代理。本地 URI 不变。下载、解码、透明边缘准备全部成功后才显示；加载中和失败时均无图，无占位、进度或错误图标。

## 9. 圆点指示器

- 固定在节目区底部、相对整屏水平居中，使用第 7.1 节高 24dp、最大宽 288dp 的独立指示带，不再跟随右侧图片的位置。
- 去掉左右箭头和 `1 / 2` 数字。
- 一个有效节目对应一个标记，数量始终等于全局有效记录数；不会因下方聚焦的 App 变化。
- 普通项为较暗的小圆点，当前项变为亮色的长椭圆。示意初值：圆点约 7dp，当前项约 25×8dp，过渡约 280ms。
- 切换时旧项收回圆形、新项伸长，同时变化颜色；使用现有 `Motion`，可打断的尺寸动画可用阻尼弹簧。
- 手动跨首尾与自动循环时，当前标记始终与真实顺序中的选中记录同步；首尾衔接不增加占位或复制圆点，也不重新排序记录。
- 指示器只表达当前节目，不获取遥控器焦点，也不拦截触摸或鼠标点击；亮椭圆不表示另一个可点击控件被选中。
- 数量较多时只允许内部圆点轨道横向滚动，保持当前项可见，外部指示带不移动、不换行；不能用固定五个点冒充真实数量。
- 当前点伸长和收回时，指示带的中心及上下边界不变。可加很轻的局部暗色底或描边，保证亮背景上的对比度；该对比度处理只作用于指示带，不加到海报边缘，也不增加全屏遮罩。
- 只有一条时保留一个当前标记，左右操作不产生切换位移或重复打开，不启动自动轮播；没有记录时隐藏指示器，不执行节目切换。

指示器相对首页内容独立绘制，在壁纸、海报、文字、应用底板及焦点效果之上；位于网格滚动与图片裁切容器之外。不能试图仅靠子节点的 `zIndex` 穿出父级，因为它只调整同一父级内的绘制顺序。

最低改动的接法是把节目和指示器挂在现有首页内容容器中、滚动子容器之后，复用该容器已有的截图、隐藏与遮挡处理；菜单、设置、屏保等仍使用原来的浮层绘制顺序。浮层、移动模式或屏保出现时暂停节目交互并隐藏指示器，避免为了它提高全项目浮层的 `zIndex`。不能把独立指标画到已被首页截图替代的内容之外继续刷新，也不能假定较晚绘制的默认层级菜单能盖住任意高层节点。层级保护与第 7.1 节的 16dp、12dp 空间约束同时成立。

## 10. 遥控器、焦点与生命周期

交互上区分 `Programs`、`Apps`、`Status` 三个焦点区域。它们是功能边界，不要求把现有首页焦点状态重写成新状态机；节目键不能混进应用网格的 `focusedKey`，全局列表与当前节目键独立于 App 焦点。新增功能保存节目选择与节目焦点意图，App／状态胶囊仍复用原来的 requester、`focusedKey` 和 `pillFocused`。首次进入、浮层关闭、HOME、App 消失等决策接入原恢复链，不能另起一组无条件请求焦点的 Effect 与首页互相抢焦点。

节目区同时遵循宿主现有的交互许可。儿童与长辈模式锁屏覆盖首页时，隐藏节目与指示器，不接受节目导航、播放或恢复焦点；解锁后的目标仍由原焦点恢复链决定。锁屏和 PIN 的判断保留在宿主，功能只接收结果。设置入口的 PIN 保护与受限模式锁屏含义不同，不能因为 `AerialSettings.locked` 就额外禁止全部普通视频 App。

| 焦点区域 | 操作 | 行为 |
| --- | --- | --- |
| 首次进入 | 有有效记录 | 选中排序后第一条的「继续播放」 |
| 首次进入 | 无有效记录 | 选中第一个 App；无 App 时回退到状态胶囊 |
| 节目区 | 左／右 | 按全局列表真实顺序双向循环：末项向右回首项，首项向左回末项；焦点保持在节目区 |
| 节目区 | 确定 | 执行当前节目的播放入口 |
| 节目区 | 下 | 回到进入节目区前的最后一个 App；首次进入时回第一个 App |
| 节目区 | 上 | 进入右上角状态胶囊 |
| 第一行 App | 上 | 有记录时选中当前「继续播放」；没有时进入状态胶囊 |
| 第二行及后续 App | 上／下 | 按网格规则移动到同列相邻行，不改变节目列表和当前项 |
| 任意 App 行 | 左／右 | 按网格规则选择 App，不改变节目列表和当前项 |
| App 图标 | 确定 | 正常启动这个 App，不播放上方节目 |
| 状态胶囊 | 下 | 恢复进入胶囊前的有效焦点区域和目标 |
| 状态胶囊 | 返回 | 沿用首排规则，根据现有设置启动屏保 |
| 首页 | HOME | 回第一个 App；保留全局列表和当前节目，不重新选第一条 |

手动与自动切换使用同一份排序后的有效记录列表。节目区按右前进一条、按左后退一条，可以连续跨首尾无限循环；跨首尾只是选中相邻记录，不重置来源开关、汇总范围或下方 App 的焦点与滚动位置。来源栏、标题、图片、播放入口和当前圆点同步到新记录，来源栏按新记录显示真实 App。

节目区始终暂停自动轮播，手动循环不会重新启动计时任务，也不会把焦点转移到 App 或指示器。零条记录时不执行节目切换，沿用无记录的普通桌面与焦点规则；单条记录时保持该项，左右操作不产生位移、切换动画或重复打开，自动轮播也不启动。左右只用于浏览，只有确定才执行播放入口。

因此第二行的完整路径是：第二行 App → 按上到第一行同列 App → 再按上进入节目。途中没有来源变化；进入节目区时取消轮播并锁定眼前的那一条。之后按下返回入口所在的首排 App。

返回键保持以下规则：

- 菜单、设置、文件夹和移动模式先处理各自的返回，不被节目区截走。
- 应用网格深处返回首排；首排根据 `backStartsScreensaver` 启动屏保。
- 新增节目区按返回，同样根据该设置启动屏保；关闭该设置时消耗事件，不退出桌面。
- 返回键不承担“浏览记录”或“切换来源”的功能。

首次查询与用户输入存在竞争时：先让桌面可操作；数据回来后，只有用户还没操作且初始焦点任务仍有效，才把焦点放到第一条节目。用户按过方向键、HOME 或打开菜单后，迟到结果只能更新内容，不能抢焦点。

从播放 App 返回、关闭菜单、状态面板返回和屏保唤醒，都恢复此前有效的节目键与焦点目标，不等同于再次首次进入。屏保唤醒继续吞掉用于唤醒的那次按键。原 App 或节目已移除时选择相邻可用项，滚动位置限制到合法范围；需要返回 App 但已经没有任何可用 App 时，统一回退到状态胶囊。

## 11. 自动轮播与动画

自动轮播仅在以下条件同时满足时运行：

```text
masterEnabled && systemPermissionGranted
&& previewVisible && homeInForeground && windowHasFocus
&& homeInteractionAllowed
&& focusRegion == Apps
&& overlay == None && movingApp == null && !screensaverVisible
&& effectiveRecords.size >= 2
```

规则与建议初值：

- 在任意 App 行停留时，对全局列表每 8 秒向右前进一条；最后一条回到第一条，与手动向右切换的顺序及首尾衔接一致。零条或单条不启动自动轮播。
- 完成上一段转场后再开始计算完整停留时间。用户导航后重新计时，便于稳定阅读当前内容。
- 进入节目区时先取消任务、锁定当前节目键，再转移焦点；随后确定打开的必须是眼前这一条。
- 进入浮层、后台、屏保、移动模式或失去窗口焦点时暂停；恢复后重新计时，不补播错过的次数。
- 局部海报按第 7.2 节使用 320ms 淡入、轻微缩放与回位。内容按用户确认的联动方案作为一组：旧片名、资料、独立进度与播放按钮在 120ms 内退移最多 10dp 并淡出，完全隐藏后交接内容，间隔 20ms，新组在 300ms 内从相应侧最多 16dp 处轻移淡入。左右方向镜像，圆点跟随显示内容键交接。使用项目已有 `Motion`，尊重减少动画设置。
- 背景增强采用用户确认的 B 柔边推移，520ms、Motion.EaseOut，左右方向跟随导航。大部分区域仍分区裁切，仅接缝约 56dp 混合；首尾收窄混合带，用局部重叠的位移保持原图构图，不要求缩放或额外裁掉壁纸边缘。不增加整屏透明混合或实时模糊。转场留在功能内，不修改全项目的动画组件；相邻转场之间保持静态。
- 自动切换不请求焦点、不模拟遥控器按键、不播放按键音，也不更新 `lastInputAt`；不能因此阻止屏保启动。

基础接入没有全屏节目图遮挡原壁纸，航拍／视频仍按现有首页规则运行。背景增强才需要协调遮挡：节目横图完全覆盖原背景时，应通过现有播放器宿主入口暂停或释放被遮挡的播放，保留原壁纸选择与播放位置，退出后按原规则恢复；不在播放器内部加入 Watch Next 状态。

## 12. 播放入口与失败处理

优先解析记录的 `intent_uri`，检查可执行目标与来源归属，正常跳转到来源 App。点击前冻结选中记录，避免轮播或刷新改变目标。

深链缺失、解析失败或启动失败时，尝试正常启动来源 App，并明确只能打开 App，无法保证从该节目的进度继续。来源已不可用时刷新列表并给出一次简短提示，不能留下不可点击的主按钮。

成功跳转应接入现有的“已从首页打开 App”生命周期标记，使播放返回恢复焦点；不能每次 `onResume` 都初始化为第一条。当前 `MainActivity.open()` 用于设置入口，既不设置 `openedAppSinceHome`，又会吞掉异常并执行设置专用回退，不能直接作为节目播放接口。增加一个很薄的节目启动回调：解析、来源校验和失败决策留在功能内部，Activity 负责宿主前置校验、实际启动、生命周期标记及返回结果。

当前 `MainActivity.launch()` 已有受限模式与 PIN 检查，深链和正常启动来源 App 都必须遵守它们。确有两条启动路径共用的逻辑时，可以提取最小私有校验／结果接点，保留原系统兼容处理；不复制整段 `launch()`，也不把它的 `Unit` 返回当成启动成功。启动回调需区分“已发起启动”“被限制或等待解锁”“目标不可用或启动失败”；前两种不能被当成失败而再次回退启动，PIN 取消后也不继续执行旧请求。“已发起启动”只表示启动调用成功，不承诺视频已开始播放。

## 13. 接入边界与上游同步策略

本节于 2026-11-03 按仓库 `bf64c30` 的现有结构复核，约束未来实现，不表示代码已经接入。减少合并成本的重点是明确职责、复用已有行为，并控制现有文件的修改位置。文件数量不作为解耦程度的指标，也不能承诺同步上游零冲突。

### 13.1 功能集中在新增目录

在现有 `app` 模块中新增普通 Kotlin 包，不新增 Gradle 模块、插件机制、全局事件总线或通用首页框架。建议职责如下，文件划分可按实际规模合并：

```text
app/src/main/java/app/orchard/tv/watchnext/
  WatchNextModels.kt       Records, capability and loading state
  WatchNextStore.kt        Feature preferences
  WatchNextRepository.kt   Provider access and observation
  WatchNextViewModel.kt    Derived state, commands, selection and carousel
  WatchNextHost.kt         Permission, lifecycle and host binding
  WatchNextPreview.kt      Content, controls, indicators and UI transitions
  WatchNextArtwork.kt      Image preparation and bounded cache
  WatchNextHomeLayout.kt   Pure program-area geometry
  WatchNextLaunch.kt       Intent validation and launch decisions
```

- `WatchNextStore` 使用独立的 `SharedPreferences("watch_next")` 保存总开关及来源集合，不扩展 `AerialSettings`，不迁移或修改已有设置。系统授权每次查询真实状态，不把偏好值当作授权结果。
- 功能自己的 ViewModel 统一协调有效列表、当前记录、待授权操作及刷新／轮播任务；`HomeViewModel` 只提供已经存在的首页与 App 状态，不新增 Watch Next 数据职责。实际读表、解码和缓存各归对应服务，计时、查询、图片缓存都不写进 `HomeScreen`。
- Host 在首页稳定组合节点创建一次。菜单和个性化入口共用同一实例，不能随着菜单关闭销毁权限请求器或各自启动 Repository。Host 的存续不依赖记录非空：开启且授权有效、首页可见时，即使当前成功读到空表也保留监听；非空条件只控制节目 UI、焦点目标及轮播。旧系统返回不支持，不触达需要 API 26 的读取路径。已有 `activity-compose`、`lifecycle-viewmodel-compose` 足够，无需升级依赖。
- 权限请求可在 Host 使用现有 Activity Result API；由首页传入 `vm.resumed`、窗口焦点、浮层、移动、屏保、交互许可及输入时间的只读值，不在 Activity 的每个生命周期回调中分散添加刷新，也不修改屏保计时器。
- 来源映射使用宿主提供的目录快照与展示范围；功能代码不接管 App 排序、移动、文件夹、隐藏规则或应用枚举。新增 helper 只接收需要的值和回调，不传入整个 `HomeViewModel`、`Restricted` 或 `Wallpapers` 对象。
- 五种语言分别新增 `res/values/watch_next.xml`、`values-zh/watch_next.xml`、`values-ru/watch_next.xml`、`values-uk/watch_next.xml`、`values-kk/watch_next.xml`，资源名使用 `watch_next_` 前缀、占位符保持一致。避免为此反复编辑上游的大型 `strings.xml`。

#### 状态归属与职责

| 状态／职责 | 负责者 | 边界 |
| --- | --- | --- |
| 系统能力、真实授权 | Android 系统；Repository 读取前复核，Host 负责授权交互 | 功能状态只保留本次检查结果；不把授权保存为自己的永久布尔值，不由菜单自行判断 |
| 总开关、来源集合 | `WatchNextStore` | 作为持久偏好的唯一来源；所有入口经同一组功能命令修改，不各自操作 `SharedPreferences` |
| 原始记录快照、查询代次、Provider 监听 | `WatchNextRepository` | 同一功能会话最多一个观察流；不认识首页焦点、网格、菜单或壁纸，不因结果为空自行停止观察 |
| 有效列表、当前节目键、待授权请求、轮播任务 | `WatchNextViewModel` | 从快照、偏好和宿主事实派生；选中下标、圆点数和菜单开启态不另存可独立修改的副本 |
| 图片请求、解码、透明边缘预处理、有限缓存 | `WatchNextArtwork` | 由同一功能会话管理生命周期；UI 不各自启动加载器，不复用壁纸的选择状态或整套缓存 |
| 节目局部动画、指示带滚动 | `WatchNextPreview` 的组合状态 | 依据当前节目键及图片结果展示；动画完成回调不能回写旧选择，不负责查询、解码或授权 |
| App／状态焦点、网格滚动、浮层、HOME、截图、屏保 | 原首页及现有宿主 | 功能只报告节目可聚焦性及恢复意图；实际焦点请求仍由原恢复链执行 |
| 权限请求器、生命周期收集、功能与首页的连接 | `WatchNextHost` | 不再保存第二份列表、偏好或焦点事实；ViewModel 不持有 Activity、`FocusRequester` 或 Compose 滚动状态 |

这些是职责边界，不要求每一行都拆出一个接口或单独文件。图片预处理与展示动画需要分别管理；Host 负责连接，不能变成同时处理 Provider、布局、偏好和启动的总控制器。

#### 小接口与依赖方向

| 连接 | 最小输入／输出 | 约束 |
| --- | --- | --- |
| 首页 → Host | 来源元数据及允许范围、前台／窗口焦点、浮层／移动／屏保、交互许可、焦点区域、最近输入时间 | 传只读事实，不传整个可变首页模型；功能不轮询首页内部字段 |
| Host／ViewModel → 首页与入口 | 只读节目状态、总开关／来源行状态、可聚焦性，以及少量操作回调 | 首页与菜单直接渲染派生结果，不重新计算另一套开启规则 |
| 展示组件 → 功能 | `setMasterEnabled`、`setSourceEnabled`、`advance(delta)`、播放当前项等具体操作 | 一项操作走一个入口；不必增加全局事件总线或通用命令框架 |
| 功能 → Activity | 固定记录身份的启动请求，以及明确的启动结果回调 | 宿主执行并复核现有启动限制；功能处理深链与回退决策，不直接绕过宿主 `startActivity` |
| 首页 → `WatchNextHomeLayout` | 实测画布、网格可见边界、文字及图片区约束 | 只返回节目边界和网格预留尺寸；不接收私有 `GridMetrics`，不持有滚动状态，不请求焦点 |
| Host → `WatchNextPreview` | 只读内容状态、图片结果、布局尺寸及操作／焦点回调 | 展示组件不自行取得 ViewModel、查询 Provider 或读写偏好；焦点 requester 留在组合层并连接宿主恢复链 |

依赖方向为：首页适配层 → 功能状态与命令 → Repository／Store／Artwork；展示层 → 只读状态与现有 UI 组件。Repository、Store 和图片服务不反向依赖 `HomeScreen` 或 `HomeViewModel`；现有共享 UI、壁纸和播放器也不引用 Watch Next 类型。几何 helper 只计算数值，业务状态不依赖 Compose 布局对象。

授权请求及系统返回经同一个 Host 和待授权请求处理。请求结果应用前检查该操作是否仍有效；用户随后关掉总开关或取消操作，迟到授权结果不能重新开启展示。读表资格、节目展示资格、轮播资格分别派生，遵循第 6、10、11 节，不合成一个含义不明的 `active` 开关。

#### 优先复用的能力

| 已有能力 | 复用方式 | Watch Next 自己补充的部分 |
| --- | --- | --- |
| 应用目录、名称、图标及已有缓存 | 首页适配层在目录变化时构造来源快照，沿用真实 App 的名称与图标引用 | 包名与 Provider 记录关联；不另建应用扫描或图标缓存系统 |
| `GridMetrics`、App 绘制循环、焦点恢复链 | 在原调用点连接预留尺寸、裁剪边界和节目焦点目标 | 纯节目几何与可聚焦性；不复制网格算法或维护第二套 App 焦点 |
| `AppTile` 的外部 `Modifier` | 调用处注入所需的 `focusProperties` | 首排与节目区的方向连接；文件夹中的磁贴继续使用原行为 |
| `MenuRow`、个性化的 `SettingRow / Choices` | 在各自现有文件内加可选行，传状态和回调 | 来源开关与总开关的文案、派生状态；私有设置组件无需为此全部公开 |
| `Pressable`、`LiquidGlass`、`Motion`、`Palette / Type` | 继续播放直接组合既有控件与材质，继承长按抬起保护、焦点及性能降级 | 节目信息、图片透明边缘和圆点局部转场；不复制按钮或毛玻璃实现 |
| 宿主启动、受限模式／PIN、返回标记 | 通过一个薄回调复用已有检查与启动能力；确有共用需求时抽取最小私有接点 | 深链解析、来源校验及失败决策；不复制厂商兼容分支或重建访问规则 |
| `Images` 中语义适合的图片工具 | 核对输入类型、缩放方式、内存所有权后直接调用 | URI 加载、等比 Fit 与四边透明渐变；`decodeCover()` 会裁切，不能用于本设计的完整海报，`frost()` 仅供背景增强按需复用 |

功能内部也共用行为：菜单和个性化使用同一组开关／授权命令，手动左右与自动轮播使用同一个 `advance(delta)`，刷新后选择修正、圆点、图片及播放目标都从同一当前节目键派生。菜单显示、点击处理和播放执行均不各自保存一份“当前节目”。

只在系统读表、实际启动等确有隔离或验证需要的边界引入接口；其余优先使用普通类、纯函数、只读数据和直接回调。现有能力缺少必要入口时允许补一个小接点，不为了少改一个旧文件而复制实现，也不提前建设通用 Provider、权限、轮播或首页插件框架。

### 13.3 首页必须处理的真实耦合

**固定节目区与深层 App 网格是基础接入最大的集成点，无法仅插入一个组件解决。** 当前 `GridMetrics.restY / scrollFor()` 假设网格可占用整个首页；时钟与 App 的滚动、底板、背景磨砂和影片状态也有联系。需要保留一个仅节目实际可展示时生效的预留区域与网格裁剪分支，确保第二行及更深行不会滚到节目、按钮和圆点下面。

处理原则：

1. 复用原 `GridMetrics`、同一个滚动状态和同一份 App 绘制循环。功能 helper 只根据实测边界计算新增节目几何与预留空间；`GridMetrics`、滚动量及同列 App 目标仍由首页原调用点负责，通过少量参数或局部计算值接入。不得把私有 `GridMetrics` 搬进功能包，或复制一份 `HomeScreen`／`GridMetrics` 再长期手动同步。
2. 功能关闭、不支持、未授权或无有效记录时走原布局与焦点路径；不通过改写 `AerialSettings.oneRowHome`、时钟大小或用户选项实现切换。有节目时也保留原时钟设计；节目图片尺寸等临时展示值不能落盘覆盖原设置。
3. 首次焦点、浮层关闭、App 消失、HOME 和状态胶囊 Down 接入原来的恢复决策。功能只增加“节目是否应恢复”的目标，不替换 `focusedKey`，不创建和原 Effect 竞争的请求焦点任务。节目变空时先用原入口恢复有效 App／状态焦点。
4. [AppTile](../app/src/main/java/app/orchard/tv/ui/home/AppTile.kt) 已支持外部 `Modifier`，方向键通过 `moveFocus()` 工作。优先在 HomeScreen 调用处条件注入 `focusProperties`，连接首排 Up→节目及同列目标；不预设必须修改 `AppTile.kt`，也不影响文件夹内复用它的导航。
5. 节目组件复用首页已有的整体隐藏、控制中心截图和个性化遮挡边界，位于网格滚动容器之外。圆点只在首页内容内部使用必要的绘制顺序；浮层／屏保出现时隐藏，避免改动全项目的浮层层级。
6. 启用态几何还需校准原 `inGrid`、底板与背景滚动参数，不能为了固定节目让其他视图读到不一致的滚动进度。需要验证 4／5／6 列、单双排、名称及焦点放大；空间不足时在节目组件内部收紧次要信息或隐藏局部图片，不能用遮盖 App 焦点来回避布局问题。

本次实现已在原 HomeScreen 中连接固定视口、裁剪和焦点恢复，没有复制首页或 GridMetrics；具体改动见第 17 节。这不是只插入几行的接点，后续同步上游时仍须单独审阅并重点回归。

## 15. 实现前仍需落定的事项
