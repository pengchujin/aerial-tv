# Top Shelf：第一排 App 的应用内容

状态：**已确认，已实现**（2026-10-22）；模拟器和索尼真机（Emby）验证通过。实现时的偏差见文末「实现记录」。

## 目标

像 Google TV / Fire TV / tvOS 的 Top Shelf：焦点停在**第一排**某个 App 上时，屏幕上半部分换成这个 App 自己发布的内容（继续观看、推荐），以一排可左右滑动的海报卡片呈现；按「上」进入卡片，按确定直接播放。App 没有发布内容时，保持现在的壁纸和大时钟。

## 已确认的决定

| # | 决定 |
|---|---|
| D1 | 卡片可交互：第一排按「上」进入卡片行，左右移动，确定键用卡片自带的 deep link 直接播放 |
| D2 | 有内容时大时钟**缩小到左上角**；切换要用连续、可打断的动画，切回没有内容的 App 时同样平滑还原 |
| D3 | 内容形式：一排可左右滑动的海报卡片 |
| D4 | 只作用于第一排；焦点进入网格后，和现在一样是模糊压暗的背景 |

## 可行性（索尼 BRAVIA_4K_VH2 / Android 12 实测）

- 数据源：系统 TvProvider（`content://android.media.tv`），表 `watch_next_program`、`preview_program`、`channel`。
- 权限：`android.permission.READ_TV_LISTINGS`（dangerous，可用 `adb shell pm grant` 授予）**就能读到其他 App 的数据**；`ACCESS_ALL_EPG_DATA` 是 signature|privileged，拿不到，也不需要。
- 实测数据：Emby 有 49 条预览、226 条继续观看，带 `title`、`short_description`、`poster_art_uri`（Emby 局域网服务器上的 http 图，最高 300px）、`intent_uri`（如 `embyatv://tv.emby.embyatv/play/358686`）。
- 奈飞：电视上装的是手机版 `com.netflix.mediaclient`，不发布任何内容 → 显示壁纸。
- 预览频道是 Android 8.0（API 26）引入的；更老的系统不启用此功能。

## 设计

### 1. 数据层 `shelf/ShelfRepository.kt`（新）

- 按包名查询，结果是 `ShelfItem(title, subtitle, posterUri, aspect, progress, intentUri)` 列表。
- 顺序：先「继续观看」（按 `last_engagement_time_utc_millis` 倒序），再按频道顺序取各**可见**（`browsable=1`）频道里的预览内容；去重（同一 `intent_uri`），最多 20 条。
- `progress` = `last_playback_position_millis / duration_millis`，有就画进度条。
- 在 IO 线程查询，按包名缓存；注册 `ContentObserver` 监听 `content://android.media.tv`，数据变了才清缓存。
- 没有权限、API < 26、查询异常、0 条：一律视为「没有内容」。
- Cursor → `ShelfItem` 的映射写成纯函数，配 JVM 单元测试（项目目前没有测试，新加 `app/src/test`）。

### 2. 图片 `shelf/ShelfImages.kt`（新）

- 支持 `http(s)://`、`content://`、`android.resource://`；3 秒超时；内存 LRU（约 30 张）。
- 卡片图按卡片实际像素解码。
- 背景图：用聚焦卡片的图，在 CPU 上预先做成「模糊 + 压暗」的全屏图（复用 `Images.frost` / `shadeForHome` 的思路），所以 300px 的低清图也不会显得糊，绘制时仍是**每帧一次全屏**。
- 图片加载失败：卡片显示标题占位，背景保持上一张或壁纸。

### 3. 布局与动画（960×540dp 画布）

- 卡片行位于时钟原来的区域，第一排（玻璃底板）上方：卡片高约 96dp，宽按 `poster_art_aspect_ratio`（16:9 / 2:3 等），间距 20dp，左边对齐网格边距 56dp。卡片下方是标题，聚焦时显示副标题和进度条。
- 状态用一个连续的进度值 `shelf ∈ [0,1]` 驱动（spring，可打断），所有变化都只走 `graphicsLayer`，不触发重排：
  - 大时钟：平移加缩放到左上角，最终尺寸与 `CornerClock` 一致；日期和天气淡出。
  - 卡片行：淡入，同时上移 12dp。
  - 背景：壁纸与内容背景交叉淡化（只在过渡期间画两张）。
- 防抖：焦点在某个 App 上停留约 300ms 才开始加载和展开，左右快速划过时不会闪；数据已在缓存里时立即展开。
- 移到没有内容的 App，或焦点进入网格：`shelf → 0`，原路还原。

### 4. 焦点

- 第一排磁贴按「上」：若该 App 有内容，焦点进入卡片行（回到上次在这一行聚焦的卡片，否则第一张）；没有内容时保持现在的行为（去状态胶囊或边缘回弹）。
- 卡片行内左右移动，行内容随焦点水平滚动（同网格的 `Animatable` 加 offset 写法）；到头时边缘回弹。
- 「下」或「返回」：回到原来那个 App 磁贴。
- 焦点在卡片上时，来源 App 的磁贴保持「浮起但未聚焦」的状态（略放大、无名字），表明这些内容来自它。
- 聚焦的卡片：放大 1.08 加阴影；背景切换到这张卡片的图（同样防抖）。

### 5. 打开内容

- `Intent.parseUri(intent_uri, URI_INTENT_SCHEME)`，加 `FLAG_ACTIVITY_NEW_TASK`；限定 `setPackage(来源包名)`，不让卡片拉起别的 App。
- 设了家长密码时，和打开 App 一样经过 `vm.whenUnlocked`。
- 打开失败时，退而打开该 App 本身。

### 6. 权限与安装

- Manifest 声明 `READ_TV_LISTINGS`。
- `tools/install.sh`：加一条 `pm grant app.orchard.tv android.permission.READ_TV_LISTINGS`（失败忽略），并同步更新 `site/agent.md` 的 Windows 第 3 步和「还原」里的 revoke。

### 7. 设置

- 个性化 → 主屏幕：新增「App 内容：显示 / 不显示」，默认显示；中英文字符串都加。

### 8. 性能与验证

- 空闲时没有持续动画；过渡期间以外每帧只画一张全屏图。
- 在电视上用 release 版加 `compile -m speed` 实测：`dumpsys gfxinfo app.orchard.tv framestats`，在第一排左右移动和上下进出卡片时，90 分位帧耗时不比现在差太多（以当前版本为基准）。
- 真机走查：Emby（有内容）、奈飞（无内容）、快速连续左右划、进出卡片、确定播放、家长密码、进网格再回来、只显示一排的布局。

- `docs/ARCHITECTURE.md`：新增 Top Shelf 一节。
- `docs/HANDOFF.md`：真机验证表加一行。

## 实现记录（与上文的偏差）

1. **查询方式**：TvProvider 对没有 `ACCESS_ALL_EPG_DATA` 的调用方拒绝任何 selection 和 sortOrder（Android TV 12 模拟器：`SecurityException: Selection not allowed`）。改为三张表各读一次整表，在内存里按包名分组、整体缓存。
2. **频道可见性**：`browsable` 由系统桌面写入；一个 App 的频道都不可见时（系统桌面从没问过），视为全部可见，免得一条内容都没有。
3. **明文 http**：Emby 的海报是 `http://<局域网 IP>`，而 targetSdk 34 默认禁止明文。`network_security_config` 的 base-config 改为允许明文；Aerial 自己的 http 回退仍只有原来列明的几处（老系统上的屏保片源、天气和定位），其余请求都明确写 https。图片最大 8 MB，日志只记主机（媒体服务器把令牌放在查询参数里）。
4. **图片加载**：同时最多 3 个请求，失败重试一次，仍连不上的主机 60 秒内跳过（服务器不可达时不拖慢其他卡片）；服务器回了 404 之类不重试、也不算主机不可达（索尼上的 Emby 有几条继续观看的图是 404，之前因此整台服务器被跳过，选中卡片的背景图也出不来）。
5. **家长密码**：原来打开普通 App 不需要密码（只有电视设置需要），卡片和打开 App 保持一致，不加密码。
6. **还原**：`READ_TV_LISTINGS` 只读，和定位权限一样不在还原里撤销。
7. **选中项**：每个 App 各记一个选中项。离开卡片行、进网格再回来都保留；中间到过另一个 App 再回来，从第一张开始。行的位置、摘要和背景始终对应同一张卡片。
8. **数据变化**：Provider 的变化 1 秒防抖后才重读（播放器播放时每几秒写一次进度）；读的过程中又变了，结果先用、稍后重读。同一个 App 的数据更新时卡片行原地更新、焦点不丢；卡片的 intent 只保留 `FLAG_ACTIVITY_NEW_TASK`，去掉发布方带的 flag 和 clipData。
9. **卡片行内按「上」**：到右上角的状态胶囊（控制中心入口），胶囊按「下」回到卡片行；卡片行一直显示。
10. **移植到 1.35**（2026-10-23）：上游的时钟默认是角上一行小字，大时钟是可选项（1.27 起），所以 D2 的「大时钟缩到角上」只在选了大时钟时发生，小时钟本来就在角上、不动；右上角时同理（小时钟在状态胶囊左边）。卡片行的位置改为以第一排的玻璃底板为基准（底板上沿往上 18dp），不再依赖本 fork 早先的整条毛玻璃。选了航拍壁纸时，显示 App 内容期间航拍不播放（背景已经是卡片的图）。文件夹磁贴和信号源磁贴没有 App 内容。打开卡片时，家长密码锁着的设置类 App 和点它的磁贴一样先要密码。
11. **改成按「上」才打开，加标签和启动 App 发布**（2026-10-23，另一个实现，见 PR）：焦点在磁贴上不再自动展开，改成磁贴上方一个小箭头，按「上」才打开（D1 的「按上进入」不变，只是展开也等这一下）。卡片行在没打开时仍在组合里（透明），所以「上」有目标。多个频道时加标签。卡片行里再按「上」去控制中心的胶囊（第 9 条的 B 方案），到胶囊前记下来处，回来时回到那里；第一排最右一格按「右」也到胶囊。Aerial 给声明了 `INITIALIZE_PROGRAMS` 接收器的 App 发这个广播（每个版本一次），因为没有系统桌面时没人发，这些 App 不会建频道。
